# WatchParty
Private, single-instance Azure App Service app for exactly two allow-listed people. It streams private Blob movies through two-hour **user-delegation** SAS URLs, synchronizes playback/chat through Socket.IO, and uses WebRTC signaling with ACS TURN credentials.

## Before deploying
- Install **Azure CLI**, **Node 20**, `ffmpeg`, and optionally `azcopy`.
- This app creates resources only in `rg-watchparty` in `centralindia`. Do not run it if that resource-group name is already used for unrelated resources.
- The template deploys B1 App Service, Storage, Key Vault, ACS, and a 1000 INR/month budget. These incur charges.

## First deployment
1. Authenticate and select the intended subscription (the scripts never do this for you):
   ```bash
   az login
   az account set --subscription '<subscription-id>'
   az account show --query '{name:name,id:id}' -o table
   ```
2. Install the project dependencies once. This also installs the `bcryptjs` helper used in the next step:
   ```bash
   npm install
   ```
3. Generate a bcrypt hash **for each of the two users** and a session secret. Keep the plaintext passwords and secret private:
   ```bash
   node scripts/hash-password.js 'first-password'
   node scripts/hash-password.js 'second-password'
   openssl rand -hex 32
   ```
4. Edit `infra/main.parameters.json`. Replace every `REPLACE_*` value; use a globally unique lowercase/alphanumeric suffix of at least four characters for `uniqueSuffix`, set both emails/names/hashes, the session secret, and the budget-alert email. Do **not** commit this file after putting real values in it.
5. Preview the exact resource-group change, then create it:
   ```bash
   az group create --name rg-watchparty --location centralindia
   az deployment group what-if --resource-group rg-watchparty --template-file infra/main.bicep --parameters infra/main.parameters.json
   ./scripts/deploy-infra.sh
   ```
   Copy the `webAppName` and `storageAccountName` printed by the last command.
6. Build and deploy the application. The script installs pinned dependencies, compiles the server/client, creates a deployment ZIP, enables App Service’s Node 20 build setting, and deploys it:
   ```bash
   ./scripts/deploy-app.sh '<webAppName>'
   ```
7. Upload a browser-compatible movie and optional matching subtitle. The movie needs `.mp4` (H.264 video/AAC audio); a sibling `movie.vtt` is picked up as subtitles:
   ```bash
   ./scripts/convert-movie.sh input.mkv movie.mp4
   ./scripts/upload-movie.sh '<storageAccountName>' movie.mp4
   ./scripts/upload-movie.sh '<storageAccountName>' movie.vtt
   ```
8. Verify deployment and privacy, then open the printed URL on the two devices and log in:
   ```bash
   curl --fail "https://<webAppName>.azurewebsites.net/healthz"
   curl -I "https://<storageAccountName>.blob.core.windows.net/movies/movie.mp4"
   ```
   The unsigned Blob request must be denied (normally `403`), while the app’s authenticated `/api/movies/<name>/play-url` response provides a temporary read URL. Never share that URL.

## Decisions and limitations
- One in-memory `main` room is intentionally limited to two distinct configured users; a new tab from the same user replaces the old socket.
- V1 accepts `.mp4` plus optional `.vtt`; uploads are intentionally CLI-only.
- The ACS connection string is generated by the ACS resource and placed in Key Vault by Bicep; it is never committed in application source.

## Local development
Copy `.env.example` to `.env`, populate it with non-production values and real password hashes, run `az login` once so `DefaultAzureCredential` can access Storage, then run `npm install` and `npm run dev`. The server is on port 3000 and Vite proxies API/WebSocket requests. `.env` is gitignored.

## Security
Storage disables anonymous and shared-key access. The App Service managed identity receives Storage Blob Data Contributor and Key Vault Secrets User RBAC roles. Cookies are signed JWTs, `httpOnly`, Secure, SameSite Strict; state-changing HTTP calls require `X-Requested-With: WatchParty`. Socket handshakes use that cookie, CORS is origin-locked, payloads are validated, and socket events are rate limited. Do not log or share passwords, SAS URLs, ACS tokens, or chat content.

## Cost and teardown
B1 App Service is the fixed charge; stop it while idle with `az webapp stop -g rg-watchparty -n <webAppName>`. Hot Blob suits a small library (consider Cool for rarely watched media). Azure egress and ACS TURN relay are usage billed; monitor the budget alert. Destroy **all** resources and charges with:
```bash
az group delete --name rg-watchparty --yes --no-wait
```
