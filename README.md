# WatchParty
A private, single-instance Azure App Service app for exactly two allow-listed people. It serves private Blob movies using two-hour **user-delegation** read SAS URLs, syncs playback/chat over Socket.IO, and uses WebRTC signaling (with ACS TURN credentials available to the client).

## Decisions
- There is one in-memory `main` room; opening another tab as the same person replaces that person’s earlier socket.
- V1 accepts browser-friendly `.mp4` movies and optional sibling `.vtt` subtitles. Upload is deliberately CLI-only.
- The ACS connection string is generated by the ACS resource and written directly into Key Vault by the template; it is never committed.

## Deploy
1. Install Azure CLI, Node 20, `ffmpeg`, and (for very large uploads) `azcopy`. Run `az login` then `az account set --subscription <id>`.
2. Make both hashes: `node scripts/hash-password.js "<password>"`; make a session secret: `openssl rand -hex 32`. Put values plus a unique suffix and budget email in `infra/main.parameters.json`.
3. Deploy only the dedicated group: `./scripts/deploy-infra.sh`.
4. Deploy: `./scripts/deploy-app.sh <web-app-name>`. Open `https://<webapp>.azurewebsites.net` on both devices.
5. Convert and upload: `./scripts/convert-movie.sh input.mkv output.mp4`; `./scripts/upload-movie.sh <storage-account> output.mp4`.
6. Tear down costs: `az group delete -n rg-watchparty --yes`.

## Local development
Copy `.env.example` to `.env`, supply real bcrypt hashes and run `az login` once for `DefaultAzureCredential`. Run `npm install`, then `npm run dev`; the backend listens on port 3000 and Vite’s proxy is configured for its API/WebSocket paths. For a production-like local run, build then start the server.

## Security
The template disables anonymous blob access and shared-key access. App Service receives storage and Key Vault RBAC roles via its managed identity; source never contains Azure account keys. Cookies are signed JWTs, `httpOnly`, Secure and SameSite Strict; state-changing HTTP routes require `X-Requested-With: WatchParty`. Socket handshakes authenticate the same cookie, CORS is origin-locked, payloads are zod-validated, and event floods are limited. Do not expose `.env` or log SAS URLs/tokens/passwords/chat contents.

## Cost
B1 App Service is the fixed cost; stop it when idle with `az webapp stop`. Hot Blob is suitable for a small library (Cool may help rarely watched libraries). Movie egress and ACS TURN relay are usage billed; the template includes a 1000 INR monthly RG budget at 80% and 100%. Stay on B1 because WebSockets and Always On are required.
